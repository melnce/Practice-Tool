## Root cause

`sanitizePendingTargetInSnapshot` (f9a55e6) blanks `targetUids` / `targets` in every snapshot. That was coherent while partial target picks were **not** committed history actions — undo could only restore to a freshly-opened prompt. PR #308 deliberately made each pick of a `discard_select_hand` prompt its own committed action (`doAction("Pick Target")` per pick). Partial picks are now genuine committed state, but the sanitizer still blanks them, so position save-load restores "no picks made" and re-applying the recorded second `CHOOSE_TARGET` lands as pick #1.

## Fix

- **`picksAreCommitted`** set **once** at prompt creation in `setPendingTarget` via `inferPicksAreCommitted()` (the only place the op-name test lives).
- **`isMultiPickHandDiscard(pending)`** in `resolveTarget.ts` routes on `pending.picksAreCommitted === true` — no duplicate predicate.
- **`sanitizePendingTargetInSnapshot`** and **`captureLegalSnapshot`** skip clearing picks when `picksAreCommitted` is set.
- One source of truth for picks: live `pending.targetUids`.

## Mode path: `picksAreCommitted: selectCount > 1`

PR #264 (`applyPendingModePickIndex` in `mode.ts`):

```ts
if (partial.length < pending.selectCount) {
  doAction("Pick Mode", () => { ... }, ...);  // each intermediate pick commits
  return;
}
commitConfirmedModePicks(...);  // final pick → single "Confirm Choice" commit
```

- **`selectCount > 1`:** picks `1 … selectCount-1` each commit via `doAction("Pick Mode")` — partial picks are committed history state, same class as target discard.
- **`selectCount === 1`:** first pick goes straight to `commitConfirmedModePicks` → one `doAction("Confirm Choice")`; no per-pick `"Pick Mode"` commits.

`picksAreCommitted: selectCount > 1` is set in `setPendingModeChoice` so the sanitizer preserves `partialPickedIndices` for multi-pick mode prompts only.
